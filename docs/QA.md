# 验收闸门

一个镜头、一段配乐、一部成片交付前要过的检查。分两类：

- **工程闸门**：客观、可重复、能写成命令的检查。全部要过，交付报告里贴真实输出（命令、关键数字、产物路径），不写「应该能过」。
- **人审**：静帧人工看、审片打回、负责人看片和听片。工程闸门全过只说明「没坏」，不说明「好」。

下文写的是每道闸量什么、阈值多少、为什么，以及三部片里的实测例子。每道闸在本仓库里用哪个命令，见总表之后的「工具对照」；参数以各自的 README 为准：[beat3d](../engines/beat3d/README.md)、[paper2d](../engines/paper2d/README.md)、[filmsynth](../music/filmsynth/README.md)、[sampler](../music/sampler/README.md)。

## 总表

| 闸门 | 量什么 | 通过条件 | 什么时候跑 |
| --- | --- | --- | --- |
| 类型检查 | `tsc --noEmit` | 0 错 | 每次改完 |
| 画面确定性 | 同一帧在不同页面、不同顺序下的像素 | 逐字节相同（paper2d 整片重渲偶有 1–2 帧差几个像素，见第 1 节） | 每次改完；交付前 |
| 配乐确定性 | 同一份乐谱两次渲染 | 逐样本相同，与进程数无关 | 每次改完；交付前 |
| 拍点对齐 | `events.json` 每拍与网格的差 | ≤ 1 ms | 构建画面时自动 |
| 切点对账 | 成片里的跳变与时间线切点 | 跳变都在切点上，或在报告里列为已知 | 每次出成片 |
| 相邻帧跳变扫描 | 全片相邻帧差的排名 | 没有新出现的跳变 | 改了某一段之后 |
| 接缝 | 一镜到底交界两侧的帧差 | ≤ 该镜自己相邻帧差的 1.5 倍 | 两个程序对接时 |
| 交接帧 | 规定必须相同的两帧 | 逐像素相同（颗粒除外） | 幕间交接 |
| 回归对比 | 本版对上一版：逐帧哈希或 PSNR | 没改的帧哈希相同或 > 40 dB | 每一轮 |
| 色调档位 | 暗部、暗光、光的颜色 | 三档都在范围内 | 终调；每个镜头交付 |
| 禁用色、色带、真黑 | 禁用色像素、暗部渐变、黑场电平 | 0 帧违规；无台阶；黑场是纯黑 | 每次出成片 |
| 响度与真峰值 | 整体响度、真峰值、1 秒响度点、跨度、静音窗 | −16 LUFS 左右、≤ −1 dBTP、0 削波 | 每次渲配乐；成片音轨再量一次 |
| 音画同步 | 硬同步点起音、切点对起音 | 起音在网格 ±10 ms 内；切点落在起音 ±60 ms 内 | 每次渲配乐 |
| 叮当规则 | 叮当类分轨与混音的差 | 低至少 10 dB；安静处不出现 | 每次渲配乐 |
| 字幕可读时长 | 每条字幕的可见帧数 | 不短于经验公式 | 改了字幕或节奏 |
| 光敏安全 | 快切段相邻画面的亮度差 | ≤ 10%，单段 ≤ 1.5 s | 有快切时 |
| 交付规格 | 编码、尺寸、帧数、时长、颜色标签、体积 | 与规格一致 | 交付前 |
| 静帧人工看 | 接触表、抽帧表、全分辨率关键帧 | 无穿帮、溢出、重叠、裁字 | 每次交付 |
| 负责人审 | 看片、戴耳机听 | 负责人说通过 | 样张、全片、终版 |

## 1. 确定性

**画面。** 一帧只依赖帧号。检查方法（《一拍》《成路》的 `check-determinism`，beat3d 里同名）：开两个独立页面，页面 A 按顺序渲一批帧；页面 B 先渲几帧无关的帧热身，再倒序渲同一批；逐字节比较。不给 `--at` 时每个镜头取两帧。下面是《一拍》样张 A 的输出：

```
$ bun scripts/check-determinism.ts --at 1.3,2.2,3.1+2f,4.4,5.1,5.1+3f,6.1,6.3,6.4+8f,7.2
1.3     f32    identical
...
7.2     f400   identical
OK: 10 frames bit-identical across pages and render order
```

paper2d 一类基于 DOM 截图的渲染器还要多查一项：同一帧冷渲、接在前一帧后渲、接在远处的帧后渲，三者逐像素相同。阡陌宣传片在这里查出过 Chrome 合成层的历史依赖（移动中的字幕字形差到 92/255），最后用「每帧先隐藏合成两帧再显示」消除。paper2d 在示例片上又查到：SVG 滤镜笔触正在画的帧里，约 1–2% 的帧仍会差几个像素（每个最多 4/255），所以 `render.ts` 把帧按轮转固定分给各标签。同样的参数重渲，`--hashes` 通常逐帧相同；偶有 1–2 帧差几个像素（发布前审计同参数整片渲了 4 次，有 1 次第 113、127 帧的截图哈希不同，解码后第 113 帧 PSNR 62.87 dB）。所以先比哈希，哈希不同的帧再看 PSNR；换标签数、换后端或拿 `still` 和整片比时，直接用 `pixdiff` 或 PSNR（见 [paper2d README](../engines/paper2d/README.md)「确定性与浮点」）。

确定性只保证在同一台机器、同一个 Chrome 与 ANGLE 版本上逐位一致。换机器、换 GPU 后端（例如无 GPU 时的软件渲染）要重新建参照。

**配乐。** 同一份乐谱两次渲染逐样本相同（差值 0.0），换渲染进程数也相同。已批准的版本要有回归脚本：渲到临时目录，和批准版的混音与各分轨逐样本比较，退出码 0 表示一致（filmsynth 的 `compare` 就是这样：混音与每个分轨按 24-bit 整数比，`events.json` 去掉 `measured` 再比）。逐样本一致只在同一平台、同一锁定版本下成立；跨机器比最大差值，不比哈希。

## 2. 拍点对齐

画面引擎构建时读入 `events.json`，检查第 i 拍是否在 `i × 60 / bpm` 秒的 1 ms 以内，超了就报错退出。配乐自检里也量一遍，报告最大偏差（《一拍》样张 A：29 拍，最大 0.0003 ms）。字段与规则见 [TIMELINE.md](TIMELINE.md) 第 10 节。

## 3. 切点对账

找成片里的画面跳变，和时间线对账（beat3d 的 `bun scripts/qa-cuts.ts --in <mp4>`）：

- 跳变的判据：相邻两帧灰度平均绝对差（ffmpeg `tblend=all_mode=difference` 后的 `signalstats` YAVG）不小于阈值（默认 1/255），并且不小于前后各 5 帧差的中位数的 3 倍（中位数下限 0.5）。
- 预期切点：每个镜头的起止（含最后一个镜头切黑）、镜头内的蒙太奇切点（`shots[].cuts`），以及每个硬同步点。
- 跳变落在预期切点上：通过。跳变不在任何切点上：报 pop，退出码 1。预期切点上没有跳变：列为「软切」，应当正好是一镜到底或匹配剪辑（《一拍》的时间线用 `continuesInto` 标出这些交界，工具不读这个字段，是给人对照的）。
- 有意的跳变（例如画面里的闪白、真实录屏里 App 自己的动画）可以保留，但要在报告里逐条列出帧号和原因。

实测例子：《一拍》1080p 母版 2240 帧，用上面的判据重新扫一遍（本文档整理时实跑），得到 12 处跳变：

```
2240 frames, 12 jumps
  frame 128 24.1 3.9       ← 3.1，S02 起
  frame 954 38.3 3.5       ← S08 末尾近白（交付时已定为有意）
  frame 955 56.7 3.8
  frame 956 23.5 3.5
  frame 960 143.3 2.7      ← 16.1，硬切到真屏
  frame 1536 13.5 2.2      ← 25.1，S12 起
  frame 1728 20.5 2.0      ← 28.1，S13 起
  frame 1787 6.7 1.7       ← 真实录屏里回复发送的动画（已知）
  frame 1788 16.4 2.4
  frame 1789 12.0 2.4
  frame 1790 9.5 2.4
  frame 1920 11.1 1.2      ← 31.1，S14 起
```

5 处在切点上，7 处都已知，与制作时总验收的记录一致。

## 4. 相邻帧跳变扫描

切点对账只回答「跳变在不在切点上」。改了一段之后，还要看全片相邻帧差的排名（paper2d 的 `scan`）：输出全量 TSV，以及前 N 名的对照条（前一帧 | 这一帧 | 差 ×4）。和上一版比，前几名应当还是原来那几处（例如幕间暗幕合拢），没有新出现的。

## 5. 接缝

两个程序在一镜到底处对接时（例如一个镜头的末帧接另一个程序的首帧），在接缝两侧各渲一帧，算全画面平均绝对差，它不能大于该镜自己相邻两帧差的 1.5 倍。

《一拍》的实测：S09→S10 接缝 1.71，S09 自己相邻两帧 1.79；19.1 接缝 1.74（两侧本镜 1.82 / 1.90）；22.1 接缝 1.95（1.97 / 1.92）。接方要 import 被接方的舞台和外观，不要抄一份，抄的那份迟早会和原件对不上。

## 6. 交接帧逐像素

导演本或交接规格里写了「某帧必须恰好是某样子」「上一幕末帧等于下一幕首帧」的地方，用 ImageMagick 比：

```
magick compare -metric AE a.png b.png null:     # 输出差异像素数，必须是 0
```

颗粒层逐帧不同，比之前关掉颗粒，或者把阈值放到 ≤ 3 个码值。阡陌宣传片 H6 / H7 的三张 1920×1080 交接帧，差异像素数都是 0。

## 7. 回归对比：只改该改的帧

每一轮都要证明没改的帧没变（方法见 [METHOD.md](METHOD.md) 第 4 节）：

- **同一编码参数**：`ffmpeg -i x.mp4 -f framemd5 -` 逐帧比哈希。渲染分段、worker 数、编码预设必须和参照相同。
- **渲染器截图哈希**：多标签渲染时把每帧截图的哈希写进 TSV，两次渲染逐帧比。截图哈希比编码后的帧更干净。
- **编码后对上一版母版**：逐帧 PSNR。没改的区域高于 40 dB 算编码噪声；改动的帧应当正好是这一轮该改的帧。比较时按参照自己的矩阵与范围解码（例如 BT.601 全范围的 yuvj420p），Y 和 RGB 两个数字分开报。
- **时间对齐的自证**：同一张渲染对参照第 n 帧应当远高于对 n±1 帧（阡陌宣传片：对 n 帧 44–46 dB，对 n±1 帧只有 22–30 dB），否则先查帧号对没对齐。
- **换渲染器时的保真检查**：按固定步长抽样（覆盖所有小数帧相位），对旧母版比 PSNR，低于阈值的帧自动出对照图。再把自己的无损帧走一遍旧管线的编码，量出编码损失的底线；两者差在 0.35 dB 以内，剩下的差异就是编码损失。

## 8. 色调档位

终调时用来判断「暗部是不是这部片的墨色、光是不是这部片的光色」（《一拍》的 `qa_tone.py`，beat3d 里同名，目标写在片目录的 `tone.json`：`ink` `inkTol` `satMin` `dimHue` `lightHue` `exclude`，命令行参数可以覆盖）。按显示亮度（8 位 sRGB 上的 Rec.709 权重）把像素分三档：

| 档 | 亮度 | 判据（《一拍》的参数） |
| --- | --- | --- |
| deep 无光处 | 4–16 | 这一档像素占比 ≥ 2% 时，均值每个通道与墨色 (15, 14, 19) 相差 ≤ 5 |
| dim 暗部的光 | 16–40 | 均值饱和度 > 0.30 时，色相在 10°–30°（这部片的主色是 18°），不要品红，不要正红 |
| light 光本身 | 40–170 | 占比 ≥ 0.2% 且饱和度 > 0.30 时，色相在 12°–26°，不要红，也不要偏黄的琥珀、卡其色 |

- 每个镜头每 4 帧取一帧，缩到 480×270 再统计。遮幅是纯黑、不算墨色，先裁掉。真实录屏的镜头只报告、不判。
- 墨色、色相范围是这部片的调色板，换一部片就换参数。demo-light 的 `tone.json` 是墨色 (13, 12, 16) ±5、dim 12°–38°、light 14°–40°。
- 每一镜要有完整的阶梯：墨色的黑、主色的中间调、接近暖白的光核心。整幅只有一种中间色，就是「单调」。
- 这个工具是在终调审片时现写的：先量出问题（S03–S08 六个镜头的暗部是 351°–9° 的品红到正红，最重的一镜无光处均值是 (23, 6, 6)），再定标准；第一轮终调把光调成了琥珀色，于是又加了 light 档。

相关的三项检查：

- **禁用色**：例如《一拍》全片禁蓝：每 4 帧取 1 帧缩到 480×270，B > R+12、B > G+4 且亮度 > 24 的像素算蓝，必须 0 帧有。墨色本身 B 略高于 R，低于阈值。只管片子自己画的光和图形，真实录屏里的界面颜色不算。
- **色带**：取几帧暗场，把 0–40 拉到 0–255 看，渐变应当只有颗粒、没有台阶。暗部渐变要加抖动；编码用 `-tune grain`、`aq-mode=3`、`deblock=-1,-1` 一类参数。
- **真黑**：该黑的帧（片头之前、切黑之后）用 `signalstats` 取每帧 YMAX，有限范围下应 ≤ 16。调色的 lift 只在场景里有光时才加，否则「黑」是灰黑。

## 9. 响度、真峰值与音画同步

**整体响度与真峰值**，WAV 量一次（`filmsynth.check run` 或 `sampler.check`，两者都会再用 ffmpeg 的 `ebur128` 复核），成片里的 AAC 音轨再量一次（AAC 会让真峰值变一点）：

```
$ ffmpeg -nostats -i yipai-1080p.mp4 -map 0:a:0 -af ebur128=peak=true -f null -
  Integrated loudness:
    I:         -16.1 LUFS
  Loudness range:
    LRA:        15.4 LU
  True peak:
    Peak:       -1.3 dBFS
```

（《一拍》母版，本文档整理时实跑，与制作时的总验收一致。）

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 整体响度 | −16 LUFS（时间线 `loudness`） | 三部片都是 −16 左右 |
| 真峰值 | ≤ −1 dBTP | 0 个削波样本 |
| 1 秒响度点 | 时间线 `loudness.keys`，±3 dB | 以位置为中心取 1 秒窗；硬同步点取「之后 1 秒」 |
| 动态跨度 | ≥ 25 dB（《成路》）/ ≥ 30 dB（《一拍》） | 最响与最静的 1 秒窗之差；写明统计范围（含不含开头淡入与结尾尾巴） |
| 静音窗 | 例如「14.3–15.1 低于 −70 LUFS」 | 用最大样本绝对值确认：真静音是 0 |
| 爆音、直流 | 爆音候选 0；直流低于 −80 dBFS | 有意的瞬态（打字音起点、真实拍击）要在报告里说明 |
| 响度跳变 | 0.6 s 窗前后差 ≥ 6 dB 的点 | 只允许有意的（揭示、开头、结尾）；段落之间靠长出来和收进去，不靠台阶 |

**音画同步**：

- 硬同步点的起音在网格 ±10 ms 内。起音的定义要写死（《一拍》用的是：分轨的 2 ms 包络在目标前 80 ms 到后 150 ms 内，第一次升到窗内峰值以下 20 dB 的时刻；sampler 的 `sync_table` 用「2 ms 包络第一次到窗口峰值的 −12 dB 以内」；filmsynth 的 `sync_check` 有 `onset`、`rise` / `drop`、`bands` 几种），定义变了数字就变。
- 低频重拍可以晚 0–2 帧；涌起的峰比画面早 2–3 帧。
- 成片的硬切要落在音乐起音 ±60 ms 内（阡陌宣传片的 `ref_cuts`：逐帧找硬切，再在音频里找最近的起音）。它最早是拿来拆解参考片的：参考片的硬切几乎都落在起音上。
- 依赖外部数据的事件（例如《一拍》五块屏幕的到达音）要在成片上回量：按画面量出每个事件出现的帧，和 `events.json` 里的帧对一致。

**叮当规则**（两部 3D 片和阡陌宣传片的共同规矩）：明亮、叮当类的声音单独成一个分轨，逐秒量它与最响一层的差，必须低至少 10 dB；混音 1 秒响度低于 −30 LUFS 的安静处不出现。归类本身是判断（按频谱重心、4 kHz 以上的能量、余振长度），报告里写明是按数字归的，不是听出来的。

**接缝量表**：每个场景切换点前后各 2 秒，比较响度、每秒起音数、频谱重心，给一个变化分数；分数高的点要么是有意的揭示和推进，要么就是突兀的衔接，交负责人重点听。

## 10. 字幕可读时长

三部片用过的经验规则：

| 规则 | 出处 |
| --- | --- |
| 可见时长（格）≥ 3.2 × 字数 + 16。24 格网格下约每字 0.13 s 加 0.67 s，例如 13 字至少 57.6 格（2.4 s） | 阡陌宣传片 U90 |
| 英文从完全显出到开始淡出，至少停「字符数 ÷ 17」秒 | 《成路》功能卡 |
| 每条字幕出现到消失 70–110 帧（24 fps）；入场 8–14 帧，退场 6–10 帧，退场比入场快；同屏一行主字幕，最多加一行英文 | 阡陌宣传片对参考片的量化 |
| 全片字幕不超过 8 行，每行不超过 12 字 | 《一拍》导演本 |
| 1080p 下界面里的字不小于 14 px；投影上要读的小字（例如片尾网址）放到 20 px 以上 | 阡陌宣传片、《一拍》（片尾网址 10 px 被打回） |

做法：把每条字幕的字数、入点、出点、可见帧数列成表（例如 `captions.txt`），逐条和公式比。节奏重排、字幕压缩时，可见时长不能低于公式，也不要超过原来批准的长度。

## 11. 光敏安全

有快速硬切的段落（阡陌宣传片的材质蒙太奇）：

- 间隔 ≤ 5 帧的段落里，相邻两张的平均亮度差不超过 10%；
- 不做大面积饱和红的闪烁；
- 每段急速切换不超过 1.5 s；
- 图片按亮度渐变排序。

## 12. 交付规格

用 `ffprobe` 核对每个成品：

- 视频：编码、档次、尺寸、像素格式、颜色标签（矩阵、范围、原色、传递，四个都要打上）、帧率、帧数、时长；
- 音频：编码、采样率、声道、码率、时长与起点（和视频一致）；
- 审片拷贝的视频流应当是原样拷贝：两者的 `streamhash` 相同；音轨解回 PCM 与 `score.wav` 比偏移（0 样本）和相关；
- 分享版对母版缩放后比 SSIM（《一拍》720p 分享版 0.985）；
- 有体积上限的上传版核对字节数，并注明两遍编码不可逐位复现；
- 记录每个文件的字节数和 SHA-256。

## 13. 静帧人工看

- **接触表**：每个关键位置一张（时间线里每个镜头的起点、硬同步点、动作落点），标上位置。
- **抽帧表**：每 8 帧一张，看运动是否连贯、构图是否长时间不动。
- **全分辨率关键帧**：用图片查看工具一张张读，确认没有穿帮、溢出、重叠、字被裁掉；每个节拍至少看一帧。
- **并排对比**：同一个物体在两个镜头里要像同一个东西（《一拍》把 S12 的玻璃和已过审的 S02 并排看，S12 被打回）。
- **自审问题**写在任务书里，例如「这一帧像不像一件真的艺术品？有没有写实 3D 的面和材质？贯穿的线还在不在？这一章要讲的东西画面演出来了没有？」，或者「这三张放进顶级发布片的截图里会不会掉档次」。
- **盲测**：新开一个不带上下文的代理，只给静帧或拼图，让它逐张写看到了什么、整片讲了什么、哪几张最像电影、哪几张最像游戏截图或屏保。读错的镜头先查画面，不先改字幕；「像游戏截图」被点名两次以上的镜头回去重做。

## 14. 客观 QA 不等于听感和审美验收

工具能证明的是：没有帧坏掉、时间对得上、颜色在范围里、响度合规、该不变的没变。工具证明不了：

- 好不好看、有没有「PPT 感」、构图有没有意图；
- 好不好听、音色像不像真乐器、衔接突不突兀、有没有「AI 味」；
- 观众能不能看懂。

三部片里，工程项全过而被负责人或主会话否掉的例子很多：《一拍》样张 A 第一轮（时间、同步、确定性、色带、禁蓝都合格，画面被打回）；阡陌宣传片配乐 v6（频段占比落在参考片区间内，负责人评价叮铃声「一股 ai 味道」）、v12（跳变、爆音自检都过，负责人说「整个调不对」）。

所以每份交付报告都要：

1. 写明哪些判断来自测量、哪些来自看静帧，成片有没有在显示器上按原速播过；
2. 配乐写明「未经人耳试听」；
3. 列出最担心的 3 处，带时间码和要听、要看的问题，交负责人重点审；
4. 只有负责人能宣布听感和审美通过，主会话和子代理不替他说。
